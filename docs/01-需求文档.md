# 01 · 需求文档

> 状态：**草稿，待确认**。带「❓」的是我需要你拍板的。

---

## 1. 背景

现有链路已经跑通：一篇 Markdown → 深蓝「科技刊读风」HTML → 粘贴进公众号后台，实现零告警。
但当前形态有两个硬伤：

1. **样式写死在一套主题里**，换风格要靠改 markdown 规范文件，成本极高。
2. **依赖 AI 逐篇生成 HTML**，同一篇文章两次生成结果可能不同，且无法"发给朋友当工具用"。

所以需要一个真正的工具：本地、确定性、多主题、可分发。

---

## 2. 目标用户与场景

| 角色 | 场景 | 关键诉求 |
| -- | -- | -- |
| **我（风渡）** | 每周 1–3 篇公众号文章排版 | 快、稳、复用效果好 |
| **朋友** | 偶尔写一篇文章，想要好看的排版 | **拿到就能用，最好双击一个文件** |
| **未来的公开用户**❓ | 网页上粘贴 md 直接用 | 有网页版即可，暂无账号体系 |

**分发方式（本期）**：把整个文件夹打成 zip，通过微信文件传输发给朋友。
→ 这条约束直接决定了技术选型必须是**零安装**（见 02 文档）。

## 3. 功能需求

### P0（第一版必须有）

| # | 需求 | 验收标准 |
| -- | -- | -- |
| P0-1 | 粘贴 / 上传 Markdown，实时渲染预览 | 改一个字，右侧立即更新 |
| P0-2 | 至少 1 套可用主题（blue-editorial） | 输出与本轮 v5 视觉一致 |
| P0-3 | 「复制到公众号」按钮 | 用 Playwright 读剪贴板复核：**计算样式污染 = 0，`display:flex` 数量与源文件一致** |
| P0-4 | 导出 HTML 文件 | 可直接用浏览器打开查看 |
| P0-5 | 粘贴前本地合规校验 | 拦截 `<div>`、`class`、`id`、`<span leaf="">` 漏包 |
| P0-6 | 完全离线可用 | 断网仍能排版 |
| P0-7 | 零安装 | 朋友解压后双击 `index.html` 即可 |

### P1（第二批）

| # | 需求 |
| -- | -- |
| P1-1 | ≥2 套正式主题，可下拉切换 |
| P1-2 | 主题开发文档齐备，能照着加第 3 套 |
| P1-3 | 图片处理（本地图片转尺寸标注 `data-w`/`data-ratio`） |

### P2（以后再说）

- 多平台草稿同步（知乎 / 头条 / CSDN）
- 封面图生成

- ❌ AI 生成文案（可与现成的 Skill 配合，但不塞进本工具）

## 4. 非功能需求

| 项 | 要求 |
| -- | -- |
| **确定性** | 同一 md + 同一主题，输出字节级一致。不调 LLM、不发网络请求 |
| **离线** | 所有依赖本地 vendor，无 CDN |
| **体积** | 单个 zip 尽量 < 500KB |
| **可维护** | 新增一套主题 = 新增一个 JSON 文件，不改引擎代码 |
| **可验证** | 每篇都能跑体检脚本量化判定 |

---

## 5. 质量红线（从本轮教训固化）

这几条是踩出来的，必须写进验收：

1. **复制链接必须程序化**：`ClipboardItem` 直写原始 HTML。任何形式的手动 `Ctrl+A/Ctrl+C` 都会污染（实测 570 处脏属性 + `text-align:start` ×53 + **`display:flex` 被抹成 0**）。
2. **`text-align:left` 必须为零**：发布后的文章里若出现就说明有问题（原因见 03 文档「文字对齐异常」专节）。
3. **`135deg` 卡片底渐变数量 ≤ 主题 `rules.maxGradient135`**：超过会触发 `darkmode-no-gradient`，且手机深色模式下文字会看不见。
4. **`display:flex` 数量在"源文件 → 剪贴板 → 已发布"三处必须对得上**：对不上就是链路脏了。
5. **每张 `<img>` 必须带 `data-w` 与 `data-ratio`**。

## 6. 成功标准

**第一版算做成的标志**：

- [ ] 朋友拿到 zip，不看任何说明，双击就能把一篇 md 排出来并发到公众号
- [ ] 粘贴后编辑器**零告警**
- [ ] 体检脚本报告：计算样式污染 0、`text-align:start` 0、`flex` 数量一致
- [ ] 换一套主题只需换一个 JSON，引擎代码一行不改
