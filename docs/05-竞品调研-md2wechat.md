# 05 · 竞品调研：md2wechat

> 调研时间：2026-10-03
> 来源：https://www.md2wechat.cn/docs 、https://github.com/geekjourneyx/md2wechat-skill
> 结论先行：**它卖的是「主题库 + 云端渲染器」。这两样恰恰是我们能本地化、零成本绕开的部分。**

---

## 1. 产品形态（多入口，一个内核）

| 入口 | 形态 | 备注 |
| -- | -- | -- |
| **CLI** | `npm install -g @geekjourneyx/md2wechat` | 主力。薄客户端，真正的转换在云端 |
| Agent Skill | 给 Claude Code / Codex / WorkBuddy / Kimi / Hermes 用的操作手册 | 通过 JSON discovery 让 Agent 稳定调用 |
| Obsidian 插件 | 预览当前笔记 → 创建草稿 | |
| REST API | 需 API Key | 面向二次开发 |
| 多平台草稿 | 宿主浏览器 Agent 写入知乎/CSDN/头条/腾讯云 | v3.6.0 新增 |

**核心商业模式**：渲染在服务端，按 API Key 鉴权收费 —— **¥199/永久（统一版）**。

---

## 2. 免费 vs 付费

| 能力 | 免费「AI 模式」 | 专业 API 模式（¥199） |
| -- | -- | -- |
| 输出方式 | **生成 prompt，交给外部 LLM 继续生成** | 服务端 converter **直接返回最终 HTML** |
| 主题数量 | **3 个基础主题** | **48 个专业主题** |
| 高级排版 `:::module` 语法 | 不解析，原样当普通段落 | 支持 **59 个推荐语法 / 83 个场景条目** |
| 结果确定性 | 取决于外部 LLM | 服务端渲染，稳定 |
| 适用场景 | 作者自述是「适合实验」 | 「适合团队、客户号、矩阵号」 |

> 这条对比很关键：**免费模式根本不产出 HTML，它只生成一段 prompt 交给外部 LLM 慢慢凑**，本来就不确定，而且只有 3 个主题。
> 这解释了为什么你当初试免费版做不出他的效果。

## 3. 命令清单（值得借鉴的设计）

```
version / config init|validate / doctor      # 环境与配置体检
capabilities / themes / layout / providers   # Agent discovery，机器可读很重要
inspect     — 结构化 metadata + checks + readiness + blockers
advise      — 推荐最小增强动作
preview     — 写入最终 HTML（失败不覆盖）
convert     — 转换 + 显式执行 upload/draft 副作用
write / humanize / title suggest             # 内容生产（AI）
generate_cover / generate_infographic        # 配图
upload_image / create_image_post             # 素材到微信
sync prepare                                 # 多平台草稿预处理
```

**三条我觉得最值得抄的**：
1. **`inspect` 的理念**：先体检再动手，输出结构化 JSON + blockers。我们的 `check_published.py` 已经是这个思路的雏形，可以补强。
2. **`preview` 失败不覆盖**：避免把坏 HTML 写到旧文件上。细节但专业。
3. **`capabilities --json` 这种 discovery 命令**：给 Agent 调用时极其好用，成本极低。

---

## 4. 我们的差异点

| 维度 | md2wechat | 我们 |
| -- | -- | -- |
| 渲染位置 | 云端（按 ¥199 收费） | **本地浏览器 / Node，零成本** |
| 离线可用 | 否 | **是** |
| 费用 | ¥199 起 | **0** |
| 输出确定性 | 免费模式依赖 LLM | **确定性，同输入同输出** |
| 分发方式 | npm 装包 + 配 Key | **一个 zip，双击即用** |
| 主题扩展 | 48 个（封闭） | 自建，JSON 开放格式 |

> 我们的护城河不是"功能比它多"，而是：**本地零成本 + 零安装分发 + 确定性**。
> 它的 ¥199 恰恰是在为"云端渲染"买单，而这个需求本地就能满足。

### 必须承认的差距

- 它 48 个主题 / 65 项渲染语法，我们目前只有 1 套。**别一开始就想追平**，先把结构做对。
- 它有完整的发布链路（素材上传、创建草稿）。我们本期**明确不做**（需微信 IP 白名单，维护成本高）。

## 5. 风险与合规边界

| 风险 | 说明 | 应对 |
| -- | -- | -- |
| **微信规则会变** | 已亲历：同一套渐变写法，2026.09 发布的文章零告警，2026.10 开始被卡。规则可能在任意时区收紧 | ① 每个主题自带 `rules` 阈值；② 保留 `check_published.py` 常态体检；③ 主题文件带 `verifiedAt` 字段记录最后一次实测通过的日期 |
| **逆向他人 HTML 的边界** | 我们的做法是**学习参数与结构**（色值、间距、组件骨架），不复制他人文字内容与图片 | 主题 JSON 里只存设计参数，不存样例文案；README 注明自研 |
| **参照 md2wechat 的边界** | 命令行命名、命令清单属于公开产品信息，可合理借鉴；**不复制其主题 HTML 源码**（它的渲染结果受服务端保护，也不该抄） | 主题全部自建 |
| 单文件 App 的 `file://` 限制 | 部分 API 在 file:// 下受限 | **已实测**：`file://` 下 `ClipboardItem` 正常可用（受控实验验证） |

---

## 6. 什么时候该考虑「发出去」

三个前置条件，缺一不可：
1. ≥3 套成熟主题（只有 1 套的话公开了也没人换）
2. 至少 3 个真人朋友完整跑通过「拿 zip → 发文」全流程，没问你问题
3. 体检脚本从"我自己用"变成"开箱即用"，输出人话报错

在此之前，**本地自用 + 小范围分发**是正确节奏。
