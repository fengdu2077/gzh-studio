## 0. 先纠正一个错误：13 ≠ 组件总数

上一版文档里我写过「实际实现的 role 是 13 个，早期 18 个是照抄竞品」。
**这句话是错的，已作废。** 错在把两件事混为一谈：

| | 是什么 | 谁决定 | 数量会变吗 |
| -- | -- | -- | -- |
| **role（组件）** | 语义槽位：「这是什么」 | 引擎契约（本文） | **稳定，不随主题变** |
| **component（实现）** | 「长什么样」：`theme.components[role]` | 主题作者 | 每个主题可不同 |

- 当前 `blue-editorial` 主题**实现了 28 个 role 里的 15 个** —— 这只是它的实现覆盖率，不是 role 总数。
- 剩下 13 个走 `FALLBACK` 降级，**不报错、不留白**，只是朴素一点。
- 换一套主题，可以挑另一批来实现。**role 表不动，主题随便挑。**

> **`divider` 与 `endline` 都写作 `---`，靠位置区分**，不是靠语法：
> 文中是节奏断点 → `divider`（细线加圆点，无文字）；文末最后一条 → `endline`（END 线）。
> 分流规则在 `engine/ir.js` 的 `toIR()` 末尾，回归见 `check/test_divider.js`。
>
> ⚠️ 历史上这两者曾共用 `endline`，导致文中每插一条分隔线就冒出一个 `END`。
> 那是「两个语义被合并成一个角色」，属于 IR 层缺陷，**改主题模板修不好**（改了 END 文字会连文末一起变）。

**一句话**：role 表回答「这套工具能表达多少种内容」，主题回答「这几种内容画成什么样」。
砍 role = 砍掉工具的表达能力；砍 component = 少一套皮肤。二者绝不能混。

## 1. 设计原则

1. **语义优先**：一个 role = 一种「作者意图」，不是一种「视觉样式」。
   所以「蓝色卡片」不是 role，「结论卡」才是。
2. **正交维度分离**：同一骨架的不同情绪（提示 / 警告 / 建议）用 `tone` 字段表达，
   **不新增 role**。避免 role 爆炸。
3. **可降级**：每个 role 都必须有明确的降级目标（近亲组件 → 引擎内置朴素模板）。
   **任何 role 缺失都不能导致渲染失败或留白。**
4. **可溯源**：每个 role 必须有明确的 Markdown 来源。说不出来源的 role 不进表。

**档位说明**

## 3. 正交维度：`tone`

`tone` **不是 role**，是挂在块上的情绪标记。主题用它决定配色/图标，引擎用它决定降级。

```js
components[`${role}.${tone}`]   // 主题可精细覆盖，如 note.warn
  ?? components[role]           // 否则用通用骨架
  ?? FALLBACK[role]             // 再否则引擎兜底
```

| tone | 用在 | 默认语义 |
| -- | -- | -- |
| `info` | note | 中性信息（默认） |
| `tip` | tip / note | 建议、可复制做法 |
| `warn` | warning / note | 避坑、注意 |
| `danger` | warning / note | 强警告、会出错 |
| `success` | note | 可行、通过验证 |
| `verdict` | note | 结论、判断（**本刊风的核心卡片**） |

**好处**：将来要加「记重点卡」「避坑卡」时，**不用新增 role**，加一个 tone 就行。

## 4. Markdown 扩展语法（新增 role 的写法）

已有语法（`#` `##` `>` `-` `![]()` ``` 表格 `---`）沿用不动。

````markdown

把户型图丢给 AI 时，先说清要「可互动」而不是「渲染图」。
:::

:::warning 别直接信尺寸
AI 读出来的尺寸是估算，涉及到买家具请自己量一遍。

:::steps 三步复现
## 上传户型图
让 AI 先识别墙体和开口。
## 生成 3D 毛坯
指定比例，要求可旋转。

追问净宽、净深、动线宽度。

:::timeline
````

## 6. 新增一个 role 的流程（给后来人）

> **加组件只需改 `engine/modules.js` 一处**，详见 `docs/06` §7.1。

1. 在本文 §2 加一行，**必须写清语义 + Markdown 来源**（说不出来源的不收）
2. 在 `engine/modules.js` 加一条：`ui`（左栏）+ `grammar`（怎么提取字段）+ `fallback`（兜底模板）
   —— **没有兜底不许上线**
3. 主题 JSON 里**可选**实现；不实现就自动走第 2 步的 fallback
4. 回到本文 §5 更新覆盖率矩阵

> 不需要再改 `ir.js` / `render.js` / `index.html`。那三个现在都是读注册表派生的。
> 历史上第 2 步曾经是「9 个文件 33 处」，2026-10-06 重构收敛成本节，已验证新增组件零回归。
