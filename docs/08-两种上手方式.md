# 08 · 两种上手方式（AI 路径 / 可视化路径）

> 目标：**用户不需要记住任何排版语法。**
> 语法是给机器和主题的契约，不是给人的准入条件。本文定义两条把「普通稿子」变成「排版语法」的路。

---

## 0. 为什么要两条路

`docs/06` 定的排版语法（`:::盒子` + `@英文标签`）是为了让 IR 无歧义，**不是为了让人手写**。
证据：`samples/demo.md` 是项目自己的真实稿子，既没有文件头 YAML 也没有任何盒子 —— 连作者自己都不写这套语法。

好在这套语法不是准入条件：纯 Markdown 粘进去照样能用 —— 正文排版是对的，
首个 `#` 会自动变成刊头卡、文末 `---` 变成 END 线。
只是封面、看点、署名这些增强项，需要自己补上对应盒子。

所以语法必须由某样东西代劳。两条路，覆盖两类人：

| 路 | 适合谁 | 用户要做什么 | 用户要学什么 |
| -- | -- | -- | -- |
| **A · AI 路径** | 稿子在 AI 里写的、愿意多一次对话 | 把提示词 + 稿子一起发给 AI，粘回结果 | **零** |
| **B · 可视化路径** | 想在本地一步步搭、不想把稿子给 AI | 左栏点模块，中间改文字 | **零**（点按钮即可） |

两条路产出的都是同一份「排版语法」，进的是同一条渲染管线（`docs/06` §1）。

---

## 1. 方式 A · 把稿子交给 AI

### 1.1 流程

```
你写标准 Markdown  ──▶  提示词 + 稿子一起发给 AI
                              │
                     AI 输出排版语法全文
                              │
                     粘进 App 中间栏 ──▶ 预览 ──▶ 复制到公众号
```

### 1.2 提示词（与 `app/index.html` 里的 `#aiPrompt` 同步，改一处要改两处）

````text
你是一个公众号排版助手。我会给你一篇用标准 Markdown 写的稿子，请你把它改写成下面这套「排版语法」，然后只输出改写后的全文，不要解释、不要输出 HTML。

# 动笔前必须先确认两项账号信息
这两项跟文章内容无关，是账号级别的，不能编造：
1. 公众号名称（account）
2. 作者名（author）
它们写在 :::profile 作者卡里，跟正文完全分开，所以必须在动笔前拿到。
如果我没有告诉你，就在输出完正文之后，单独写一行提醒：
「记得把 :::profile 里的 account 和 author 换成你自己的公众号名称和作者名。」

# 排版语法（核心规则：一个盒子管一件事）

每个盒子都用 ::: 包起来，**写在哪就渲染在哪**。不要把所有信息塞进文件头的 YAML 区块里，
那会让盒子互相绑定、位置不受控。

## 1. 刊头卡（全文最前面）
:::masthead
## 文章标题
cover: 
kicker: 栏目名
issue: 2026.10
account: 公众号名称
tagline: 一句话定位

一句话导语，提炼全文最重要的那个结论。
:::
规则：cover 是封面图 URL，可选，留空会自动放占位图；不知道的字段就删掉整行，别写注释。

## 2. 作者卡（一个独立盒子；放开头就是作者简介，放文末就是署名区）
:::profile
account: 公众号名称
author: 作者名
roleline: 一行身份标签
bio: 一两句话简介
footer: 文末引导语
:::

## 3. 章节标题
## 中文标题 @ENGLISH_LABEL
@ 后面是 2~3 个单词的英文标签（如 THE CHALLENGE / BUILD IT / REFLECTION）。
序号会自动补，不要手写 01、02。末章也用普通编号，标签换 REFLECTION 或 SUMMARY。

## 4. 看点卡（章节 ≥3 个时才写，最多 3 条）
:::highlights 本文看点
- 第一条看点
- 第二条看点
- 第三条看点
:::

## 5. 正文块
- 普通段落直接写，**加粗**表示强调，`行内代码`表示专有名词
- 无序列表用 - ，有序列表用 1. 2. 3.（有序会渲染成序号标签，讲步骤时优先用有序）
- 引用别人的原话用 > 开头

## 6. 容器块（用 ::: 包起来）
:::note 结论 · VERDICT
放作者自己的判断、结论。
:::

:::compare
## 方案甲 | 推荐
- 第一条理由
## 方案乙 | 不推荐
- 第一个问题
:::

:::cta 想试试的话
引导读者做一个具体动作。
[按钮文字](链接)
:::

## 7. 媒体
- 图片：![](图片地址)，地址留空写成 ![]() 就自动放占位图
- 视频：[文件名.mp4]，公众号不能直接粘贴视频，会自动放占位图提示上传

## 8. 分隔线与文末
- 文中需要节奏断点时，单独一行写 ---，渲染成细线分隔（不带文字），可以有多条
- 全文最后一条 --- 会自动变成 END 收尾线，后面接 :::profile 作者卡收尾

# 使用纪律（必须遵守）
- 刊头卡、作者卡、END 各只能有 1 个
- 分隔线靠位置区分：文中是分隔线，文末最后一条才是 END
- :::cta 一篇最多 1 个，:::highlights 一篇最多 1 个
- 引述卡放别人的话，结论卡放自己的判断，不要混用
- 不要输出 HTML，不要输出文件头 YAML

现在，请把我的稿子改写成这套语法。
````

> ⚠️ **改提示词要改两处**：这里和 `app/index.html` 里的 `#aiPrompt`。
> `file://` 下不能 fetch，所以提示词是内联进页面的。两边不同步，用户在页面上复制到的就是旧的。

### 1.3 为什么提示词里要写「使用纪律」

这段不是装饰。`reference/theme-blue-editorial.md` 里最值钱的就是这些约束：
「全文只有 1 个 END + 1 个签名区」「行动引导一篇最多一个」「章节 ≥3 才出看点卡」。

**不写进去，AI 会给你排一篇每章都带 CTA、结尾三个 END 的东西。**

### 1.4 边界

- 只让 AI 产出**语义层**（排版语法），**绝不让 AI 写最终 HTML** —— 理由见 `docs/06` §8
- 提示词是纯文本，不依赖任何特定模型；国内外模型均可
- **可选能力**：没有 AI 也能用（走方式 B），AI 只是省事，不是必经

## 2. 方式 B · 三栏可视化工作台

`app/index.html` 三栏，**每栏独立滚动**（页面整体不滚）：

| 栏 | 内容 | 交互 |
| -- | -- | -- |
| **左 · 模块** | 按「开头 / 正文 / 结尾」分组的组件 | 点击 → 语法插到中间光标处 |
| **中 · 排版语法** | 生成的 Markdown，可直接编辑 | 改文字 → 右侧实时预览 |
| **右 · 预览** | 手机宽度预览 + 体检结果 | 体检全绿才能复制 |

### 2.1 左栏模块表

| 分组 | 模块 | 特殊规则 |
| -- | -- | -- |
| **基础信息** | 作者卡 | 独立盒子 `:::profile`，字段 `account` / `author` / `roleline` / `bio` / `footer`。**放开头=作者简介，放文末=署名区**，位置你自己决定 |
| 文章开头 | 刊头卡 | 独立盒子 `:::masthead`，字段写在盒子里的 `key: value` 行（`cover` / `kicker` / `issue` / `account` / `tagline`）+ 首个 `##` 标题 + 剩余正文当导语 |
| 文章开头 | 看点卡 | 独立块 `:::highlights` |
| 正文 | 章节标题 / 正文段落 / **无序列表** / **有序列表** / 引述卡 / 结论卡 / 对照卡 / 图片 / 视频占位 / 分隔线 | 可重复插入 |
| 文章结尾 | 行动引导 / END 收尾线 | 全文各只允许一个（左栏黄条标记） |

### 2.1.0 为什么每个盒子都必须是自包含的

曾经刊头卡和作者信息都是「文件头 YAML 里的一组字段」，带来的问题正是用户提出来的：

| 症状 | 根因 |
| -- | -- |
| 先插刊头卡、再插基础信息，基础信息跑到文件开头刊头卡旁边去了 | 两者共用同一份 `---` 区块，位置由解析器决定，不由光标决定 |
| 两个盒子根本拆不开、换不了位置 | front-matter 整篇只能有一份，所有字段被强行绑在一起 |
| 这算不上模块化 | 模块的定义就是「一个盒子管一件事，能独立存在」 |

**改法：每个模块自带全部所需信息。** 靠的是容器内的 `key: value` 行 —— 写在哪个盒子里，就归哪个盒子。
于是插入逻辑退化成一句话：**往光标处塞一段语法**，再没有「合并」「拦下」「跑到最前面」这些特例。

> front-matter 仍被兼容（旧稿和 AI 老提示词的产物还能用），但它是**降级路径**：
> 只在用户没手写同名盒子时才自动翻译成刊头卡 / 看点卡 / 署名区，且**手写优先**。
> 详见 `docs/06` §3.2。

> 「只允许一个」是**提示**，不是硬拦截 —— 硬拦截会让用户以为工具坏了。
> 真正的兜底是 `docs/06` §5.2 的降级链：就算语法写错了，也不会崩、不会留白。

### 2.1.1 封面图必须明示

`cover` 是可选字段，但**不能默默用占位图了事**，要在三处明示：

1. 左栏刊头卡模块的说明写清「留空 → 自动占位图」
2. 插入刊头卡后的 toast 直接告诉用户：`cover` 留空会用占位图，想用自己的封面就填 URL
3. 体检区：检测到封面仍是占位图时，明确提示可以在盒子里的 `cover:` 后填图片 URL

> **反面案例**：早期版本在 `cover:` 后面写行内注释提醒用户。
> 极简解析器会把 `# 说明` 当成**字段值**，封面地址直接废掉。
> 提醒只能写在md盒子外面（UI 提示 / 文档 / toast）。

### 2.2 交互要点（已实现）

- 插入后自动聚焦并把光标停在插入内容末尾，可以接着打字
- 插入位置前后自动补空行，**不会把相邻两段粘成一坨**
- 顶部「AI 用法」按钮：弹层里是方式 A 的提示词，一键复制
- 顶部「配色」按钮：改主色 + 导出/导入主题，见 §2.4
- 体检区放在右栏底部固定区，**滚动预览时始终可见**

### 2.3 布局约束（改 CSS 时注意）

- `html, body { height:100% }` + `body { overflow:hidden }` → 页面整体不滚
- `main` 是 `grid`，`min-height:0` + `overflow:hidden`
- 每栏 `.col` 是 `flex column` + `min-height:0`；内容区 `.scroll` 负责 `overflow-y:auto`
- **漏掉任何一个 `min-height:0`，flex/grid 子项就不会滚，而是把父容器撑破** —— 这是三栏滚动最常见的坑
- 窗口 ≤980px 时降为单列堆叠，每栏 `height:62vh`，各自仍独立滚动

### 2.4 配色面板（改主题不用碰 JSON）

顶部「配色」按钮打开面板，只暴露 7 个**跟主色走**的 token：

| 控件 | 影响 |
| -- | -- |
| 主色 | 标题、序号、强调 |
| 副色 | 次级强调 |
| 浅底 / 浅底 2 | 行内代码底色、卡片淡底 |
| 边框 | 卡片描边 |
| 下划线 | 链接下划线 |
| 装饰线 | 分隔线、渐变端点 |

**阴影、链接色、加粗色、渐变端点都不在面板里**——它们是引用，改主色会自己跟着变。
再给一遍旋钮只会让人不知道该动哪个，所以故意不暴露。

- 改完右侧预览立刻变
- **导出主题文件**：存成一套新主题（下拉里立刻出现，刷新后还在），
  同时下载一个 `.js` 文件。发给朋友，他用「导入主题」打开就行，**不需要装 Python**
- **导入主题**：选一个 `.js` 或 `.json` 主题文件
- **重置**：放弃改动，回到这套主题原本的配色

自定义主题存在浏览器 localStorage（`file://` 下实测可写）。
隐私模式下写不进去也不影响正常使用，只是刷新后自定义主题不在了。

> 给别人的主题是**全量快照**而不是只存差异：对方机器上不一定有原来那套主题，
> 自包含才不会打开就报错。

## 3. 两条路的验收标准

**第一次成功 ≤ 3 分钟，全程不需要读任何文档。**

| 步骤 | 时间 |
| -- | -- |
| 打开 `app/index.html` | 10 秒 |
| 载入示例 / 粘贴 AI 改写后的稿子 | 30 秒 |
| 看懂三栏分别是干嘛的 | 30 秒 |
| 改自己的标题和正文 | 60 秒 |
| 复制 → 粘进公众号，看到成品 | 60 秒 |

做不到这个数，就是门槛还没降下来，继续改 UI，不要去改 IR。
