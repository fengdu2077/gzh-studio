## 〇、盘点时发现的一件事（它改变了优先级）

之前判断「间距、字号这些非颜色 token 改不到，得等元素化重构」—— **这个判断是错的。**

事实：`themes/*.json` 里有一块 **`base`**，装的全是尺度类字段：

```
fontFamily / fontSize / fontSizeTitle / lineHeight / letterSpacing
align / paraGap / chapterGap / cardGap / itemGap
```

`engine/render.js:34` 取值时是 `Object.assign({}, theme.tokens, theme.base, block)` ——
**base 和 tokens 一样参与渲染**。也就是说：改 `base.cardGap` 立刻生效，不需要动任何代码。

所以：

- **「改间距、改字号、改行距、改对齐」这件事，本来就已经是个数据字段了，只差一排 UI 旋钮。**
- Step 1（尺度面板）**不需要**等 Step 3（元素化），也不是它的前置。

唯一要动的一处：`app/index.html` 的 `currentTheme()` 现在把 override 一律写进 `t.tokens[k]`，
而 render 里 `base` 优先级更高 —— 尺度旋钮的值必须写进 `t.base[k]`，否则会被原 base 盖掉。

**这是本清单里性价比最高的一条。**

剩下 104 处 px 字面量（22 个不同值）写在各组件的模板里，那些才会真的需要改模板或元素化。

A4 的两个方案，代价差别很大：

- **甲（推荐）浏览器 Canvas 现场生成**：App 启动时按当前主题 tokens 画三张，`toDataURL` 出来直接用。
  零依赖、配色面板一动占位图跟着变。代价 **半天**，但 `ir.js` 的 `pickSrc` 要接动态来源。
- **乙 Python 重新生成**：给 `make_placeholders.py` 加主题配色参数，重新产出 `placeholders.js`。
  代价 **1 小时**，Pillow 两个 Python 都有（12.3.0 / 12.2.0），但**每套主题要一份图**（约 20KB/张），
  且改配色面板时占位图不会跟着变。

**验收（做完这梯队，你应该能不问我就完成）**：删封面、改间距、去掉某个组件的边框、
自己造一个 `:::verdict` 结论卡并用上 —— 即 docs/09 那四条。
