# 13 · 元素化架构：落地记录

> 对应计划：`docs/10-重写规划-元素化架构.md`
> 完成时间：2026-10-07
> 一句话结论：**组件不再是「一整段 HTML 字符串」，而是一棵属性化的元素树；
> 你可以在界面上点开任意一个组件，点它内部的某个元素，逐项改字号、颜色、圆角、阴影、渐变。**

---

## 一、你现在能做什么（验收口径）

打开 App → 顶栏「主题编辑」→ **组件**页签：

| 动作 | 怎么点 |
| -- | -- |
| 改字号 / 间距 | 左边树里点那个元素 → 右边数字框改数字，全文预览立刻变 |
| 改颜色 | 取色器；旁边的文本框可以直接填 `{{accent}}` 让它跟着主色走 |
| 改圆角 / 阴影 / 边框 | 同上，都是一个个字段 |
| 背景换成渐变 | 背景那行的文本框里写 `linear-gradient(135deg,#A,#B)` |
| 某个元素只在有某字段时才出现 | 「显示条件」填字段名（如 `cover`），多个用逗号分隔 |
| 给组件加一块内容 | 选中容器 → 「子元素」选类型 → 添加 |
| 删掉组件里的一块 | 选中它 → 「删除这个元素」 |
| 让同一个 `:::card` 在 A 主题有图、B 主题没图 | 给 `image` 元素加显示条件 `cover`（本来如此），或者在一个主题里把它删掉 |

**源码模式还在**。TRANSLATOR 有保守规则，译不出来的一律保留为「原样」节点——
没有源码模式的话那部分就彻底改不了，那才叫能力倒退。

## 二、为什么不拆成 `radius` / `fontSize`，而用「有序 CSS 字典」

计划里写的是固定字段：

```json
{ "type": "box", "bg": "...", "radius": 10, "border": {"width":1} }
```

实现时发现装不下：现实的 CSS 是多值的、组合的（`margin:0 23px 0 0`、`padding:23px 21px`、
`flex:1;min-width:0`）。固定字段要么穷举不完，要么每加一种样式就得改一遍元素定义。

改成的形态：

```json
{ "type":"text", "text":"{{title}}",
  "style": { "margin":"0 0 12px", "font-size":"20px", "color":"{{inkTitle}}",
             "__order":["margin","font-size","color"], "__semi":true } }
```

- **每个值仍然是独立可编辑的字段** —— UI 按 CSS 属性名查 `GZH.CSS_PROPS` 决定给什么控件
  （数字框 / 取色器 / 下拉 / 文本框），查不到的给文本框，所以没登记过的属性照样能改。
- `__order` / `__semi` 只管输出顺序，UI 不显示、用户不需要碰。
  它们的存在是为了**忠于原文**：没有它们，翻译过来的模板渲染结果就和原来差几个字节。

**代价要说清楚**：这两个字段多少有点「元数据」的味道。但它们换来的是零回归，
而 UI 那一侧的用户体验与固定字段集完全一样（都是一个个输入框）。

## 三、迁移怎么做的

`check/build_compositions.js`，一次性把 3 套主题 × 20 个模板（主体 + 列表项 + 有序列表 + 子项）
全部翻译一遍，**写入前强制做往返校验**：

```
tree = tplToTree(tpl)
treeTpl(tree) === tpl   ← 不等就当场报错、不落盘
```

结果：**60 / 60 逐字节一致**，283 个节点里 47 个（17%）因为结构不规则保留为「原样」节点。

翻译器 `engine/tplparse.js` 的原则是保守：能干净译的译，**译出来可能丢一个字符的一律整块保留**。
它同时也是运行时的一部分——导入一个没带 `compositions` 的老主题时，App 会当场翻译出来给你编辑。

### 为什么 `components.*.tpl` 没删

1. 回归基准：下次改翻译器还能再验一遍忠实度
2. 用户手写的 tpl 覆盖（localStorage 老数据）仍然有效
3. 翻译器出问题时渲染可以立刻退回老路径
4. 没有它的主题（老主题 / 第三方主题）靠 `tplToTree` 现场翻译也能编辑

代价是主题文件大约翻倍（blue 从 35KB → 71KB）。

## 四、渲染链路怎么接的

`engine/render.js` 新增 `pickComp()`：

```
theme.compositions[role].tree   → treeTpl() → 模板串   （优先）
theme.components[role].tpl                            （退回）
GZH.FALLBACK[role].tpl                                （兜底）
```

两条路最终都收敛成**同一个模板字符串**，最后统一跑一次 `fill()`。
所以变量、条件段的语义跟老链路完全同源 —— 这也是字节级等价的基础。

## 五、这一轮踩到的坑（都写进注释了）

| 坑 | 症状 | 位置 |
| -- | -- | -- |
| 标签正则排除了 `/` | `{{/w}}` 里的斜杠让整个 `<img>` 匹配失败，退化成一堆碎文本节点 | `tplparse.js` tagM |
| 属性之间可能没空格 | `<img src=""{{?w}}` 匹配失败 | 同上 |
| `style` 里有无键片段 | `gap:10px;{{itemGap}}` 被当无效丢弃，列表间距失效 | `__I0` 注入片段 |
| span 里的空格是有意义的 | `<span leaf=""> </span>` 被过滤，分隔线高度塌掉 | `inlineText` 不过滤空白 |
| `theme.compositions[role]` 与 override 嵌套错层 | 写 `{tree: overrides.tree[role]}`，树从数组变成对象 → **改了数字预览纹丝不动** | `currentTheme()` |
| 同一个 `[data-act]` 被两层监听 | 外层 handler 的 `stopPropagation()` 掐断冒泡 → **按钮点了没反应** | 面板按钮改用 `data-eact` |
| `exportTheme` 清空 overrides 漏字段 | `overrides.tree` 变 undefined，`ovCount()` 直接崩 | 已加 `|| {}` 兜底 |
| 渲染结果体检覆盖模板体检 | 「写了 `<div>` 却不报警」 | 两种体检都显示 |

另外顺手修了两个**主题源文件里的既有 bug**：
`blue-editorial` / `blue-gradient` 的 `signature.tpl` 里 `{{/bio}}` 写成 `{{{/bio}}}`
（少右括号），会让 `fill()` 在正文里留下一个孤儿 `{`。现有的残留检测也没抓到它，
所以又在体检里补了一条「单个右括号」的检测。

## 七、还没做的

- **跨主题复用 preset**：把一个元素/一组元素存成命名片段，在多套主题里套用（现在是复制粘贴，或者导出主题再导入）。
- **预览画布上直接点选元素**（当前是「在组件面板里点元素」，改的是**组件的定义**，全篇所有同类都跟着变）。
  要做到「点某篇文章里的这一张卡、只改这一处」，还需要：给渲染出的元素打标记 → 点击命中 → 判定改实例还是改定义。
- 那 17% 的「原样」节点：可以通过给翻译器加规则继续降，优先级不高。
